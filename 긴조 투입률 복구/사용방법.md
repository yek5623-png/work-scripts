# 긴조 투입률 복구

## A1을 바꿔도 마지막 21시 명단이 남는 경우

복구 스크립트 20261118.2의 전체 재구축 후에도 실패한 경우에는 **같은 Gist의 `긴조 투입률 진단` 파일**을 새 스크립트에 전체 붙여넣어 실행하세요. 이 진단의 버전은 **20261118.3**입니다. 마지막 명단이 어디서 멈췄는지 확인하기 위한 코드이며, 기존 셀·수식·계산 모드는 변경하지 않습니다.

현재 상태출력 A1을 스크립트가 직접 읽고 원문 분리 배열·파싱 결과·근무 판정·명단·D10과 대조합니다. 사번이 같아도 상태가 바뀌었는지 비교합니다. 수식설정 B2의 시간 고정값, B3·B4의 기준 시각, 계산 모드도 표시합니다. 현재 9명이어야 한다는 기대값을 수식에 강제로 입력하지 않습니다.

실행 뒤 새 `긴조입력진단` 탭의 **A3부터 C열 마지막 결과 행까지 전체**를 댓글로 알려주세요. 원문·사번·이름은 진단 결과에 포함하지 않습니다. 14개 모의 검사 통과. 실제 업무 파일의 원인은 결과로 확인해야 합니다.

## 기존 명단 복구

최신 버전: **20261118.2**. 이전 스크립트의 코드를 아래 파일 전체로 교체하고 저장한 뒤 실행하세요.

1. 같은 Gist의 긴조 투입률 복구 파일 전체를 복사하세요.
2. 문제가 있는 Excel 웹 파일에서 자동화 → 새 스크립트에 붙여넣고 실행하세요.
3. 생성된 가장 최신 `긴조복구` 탭 1행이 `20261118.2`인지, 7행이 `복구 완료`인지 확인하세요.

정렬 함수가 이미 수정본인데도 P2에 사번이 있고 A2·D10은 0인 경우를 추가 점검합니다. 정렬 이름과 수식명단 A2·상태출력 D10 수식을 백업 후 재등록하고, `fullRebuild`로 계산 의존성을 전체 재구축합니다. 숫자 0을 사번 1명으로 잘못 세던 진단도 수정했습니다. 이번 파일의 실제 원인이 계산 의존성 문제인지는 아직 확정하지 않았습니다.

A1 원문·데일리·제외 입력·서식은 보존합니다. 사용자 정의 정렬/명단 수식은 덮어쓰지 않고 중단합니다. 출력 인원뿐 아니라 사번 목록까지 판정 결과와 일치해야 완료로 표시합니다. 실패하면 기존 이름과 두 출력 수식의 복원을 각각 시도합니다.

다시 실패하면 최신 복구 탭 **6·7·14·15·16행** 결과를 알려주세요. 14·15행은 배열 크기와 첫 칸이 숫자 0인지, 16행은 판정·명단·화면 인원을 표시합니다. 백업은 3행 C열(이름), 12행 C열(A2), 13행 C열(D10)에 있습니다.

기존 정렬 수식 모의 검사 35개와 이번 재구축·재연결·복원 검사 15개를 통과했습니다. 실제 업무 파일의 복구 성공 여부는 실행 결과로 확인해야 합니다.
