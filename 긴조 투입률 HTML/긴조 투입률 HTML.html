# SharePoint JSON 주소 연결

웹 계산형은 ‘연결 · 사용 방법’에서 SharePoint JSON 주소를 넣고 ‘SharePoint 주소 연결’을 누릅니다. 파일 주소와 AllItems.aspx의 id 파일 선택 주소를 지원합니다. 회사 주소가 미리 설정된 비공개 배포 파일은 열 때 자동 연결합니다.

30초마다 로그인된 사용자의 권한으로 읽기만 수행합니다. 기존 Power Automate의 JSON 업데이트는 그대로 사용합니다. 데이터가 바뀌면 기존 원문과 제외 입력으로 다시 계산합니다. 원문 자체는 자동 수집하지 않으므로 상태가 바뀌면 새 원문을 붙여넣으세요. 수기 입력은 다른 사용자에게 공유·저장하지 않습니다.

주소 통신 허용 범위는 SharePoint HTTPS이며 외부 CSS·JS는 없습니다. 미리보기의 sandbox·CORS·로그인 정책을 우회하지 않습니다. 실패하면 마지막 결과에 오류를 표시하고 재시도합니다. ‘오류 상세’에는 HTTP 상태·실패 방식·실행 주소·마지막 성공 시각을 표시하며 직원 원문은 포함하지 않습니다. JSON 원본 열기는 로그인·읽기 권한을 별도로 확인하는 버튼이며 미리보기 제한을 해제하지 않습니다.

실제 회사 환경에서 연결 성공 여부는 확인이 필요합니다. HTML의 통신 허용 설정을 바꿔도 SharePoint가 부여한 sandbox 제한을 해제할 수는 없습니다.

아래는 PC 파일 연결 및 엑셀 연결형의 기존 안내입니다. 웹 계산형의 주소 연결에는 동기화 폴더가 필요 없습니다.

# 긴조 투입률 HTML — 업무 PC 설치 안내

## 먼저 알아둘 점

- 업무 PC에서 GPT, ChatGPT 계정, Node.js, Python을 사용하지 않습니다.
- 두 HTML에 CSS와 JavaScript가 모두 들어 있습니다. 인터넷 라이브러리도 내려받지 않습니다.
- SharePoint에 HTML을 올리는 것만으로 앱이 실행되는 것은 아닙니다. 문서 라이브러리에서 HTML을 다운로드한 뒤 Edge 또는 Chrome에서 여세요. 최신 SharePoint 페이지는 임의의 JavaScript 붙여넣기를 허용하지 않습니다.
- 실제 Excel 연결에는 회사 Microsoft 365의 Office Scripts와 Power Automate 사용 권한이 필요합니다. 회사 정책으로 막혀 있다면 관리자의 허용이 필요하며, HTML에서 우회하지 않습니다.
- 처음에는 현재 정상 작동하는 상태출력 파일의 복사본으로 시험하세요. 원본 데일리는 읽기만 합니다.
- 공개 Gist에는 회사 주소, 실제 원문, 직원 명단, 인증 정보가 없습니다. 개인 다운로드 묶음의 `회사 연결설정.json`은 주소만 담고 있으며 공개 업로드 대상이 아닙니다.

## 두 버전

1. `긴조 웹 계산형.html`: Excel에서 데일리만 읽습니다. 원문 붙여넣기, 제외 10명, 분 환산, OT, 허용률, 지각 확인, 차이 후보를 브라우저가 계산합니다. Excel 원본을 수정하지 않습니다.
2. `긴조 엑셀 연결형.html`: 현재 Excel의 계산 수식을 그대로 사용합니다. 웹 입력은 회사 폴더를 거쳐 Excel에 접수되고 결과 JSON이 돌아왔을 때 표시됩니다. ‘엑셀 결과 새로 읽기’는 원문·제외 입력을 바꾸지 않습니다.

현재와 다음 시간은 동일한 기준표를 사용합니다. 목표 11.4명은 87~118%, 목표 14명 초과는 95~105%입니다. 1명 이하 구간의 최대 10은 1000%입니다. 경계와 같은 값은 정상이며, 필요한 조정분은 충분한 정수 분으로 올림합니다.

## 가장 먼저 5분간 수동으로 시험하기

### 웹 계산형

1. 원본 데일리 Excel을 회사 계정으로 엽니다.
2. 자동화 → 새 스크립트에 `스크립트/데일리 웹 내보내기.txt`를 붙여넣고 저장·실행합니다.
3. 출력의 `{`부터 `}`까지 JSON 전체를 복사합니다. 해당 운영일 탭을 자동 선택합니다. 00~04시는 전날 운영일입니다.
4. HTML의 ‘연결 · 사용 방법 → JSON 붙여넣기’에 넣습니다.
5. 실제 A1 원문을 붙여넣고 ‘웹에서 계산’을 누릅니다. 샘플에서 실제 파일로 바꾸면 샘플 원문은 지웁니다.

### 엑셀 연결형

1. 상태출력 복사본에 `스크립트/긴조 투입률 업데이트.txt`를 한 번 실행해 20261116.6을 설치합니다.
2. 같은 파일에서 `스크립트/상태출력 웹 내보내기.txt`를 저장·실행합니다.
3. 출력 JSON을 HTML의 ‘JSON 붙여넣기’로 불러옵니다. 기존 Excel 결과가 나타나는지 확인합니다.
4. 아래 자동 연결을 구성한 뒤 원문을 웹에서 접수합니다. 입력이 실제로 반영되기 전에는 ‘엑셀 처리 대기’로 표시합니다.

## 회사 폴더 만들기

쓰기 권한이 있는 회사 SharePoint 문서 라이브러리에 `긴조웹` 폴더를 만들고 아래처럼 구성합니다. 폴더 위치는 회사에서 허용하는 곳으로 정하세요.

```
긴조웹/
  데일리.json
  상태출력-결과.json
  요청/
  결과/
```

처음 두 JSON은 각 내보내기 스크립트의 실제 출력으로 만듭니다. 빈 `{}`나 샘플 파일을 실제 자료로 사용하지 않습니다. 웹 계산형만 쓸 때는 `데일리.json`만 있으면 됩니다.

회사 PC에서 이 폴더를 OneDrive로 동기화하고 ‘항상 이 장치에 유지’를 선택합니다. HTML의 ‘동기화 폴더 연결’에서 바로 이 `긴조웹` 폴더를 고릅니다. Excel 연결형은 접수 저장을 위해 읽기/쓰기 허용이 필요합니다. 웹 계산형은 읽기만 요청합니다.

폴더 접근이 브라우저나 회사 정책에 막히면 ‘JSON 직접 불러오기’ 또는 ‘JSON 붙여넣기’를 사용합니다. 폴더 선택이 되는 경우에만 5초마다 파일 변경을 확인합니다. 이 5초는 회사 흐름·OneDrive의 실제 처리 속도를 보장하는 시간이 아닙니다.

## Power Automate A — 데일리 자동 내보내기

1. 회사 Power Automate에서 예약된 클라우드 흐름을 만듭니다. 주기는 **5분**, 시간대는 Seoul로 설정합니다. Office Scripts 실행 제한을 고려해 1초·수초 간격으로 만들지 않습니다.
2. Excel Online (Business) → **스크립트 실행**을 추가하고 원본 데일리 월 파일과 `데일리 웹 내보내기`를 선택합니다. 작업 이름을 `Run_daily`로 바꿉니다.
3. `기준시각`은 비워 두면 실행 시각을 사용합니다. 05시 이전에는 전날 운영일 탭을 읽습니다.
4. SharePoint → **파일 업데이트**로 회사 `긴조웹/데일리.json`을 선택합니다. 파일 내용에는 `Run_daily`의 동적 콘텐츠 **result**를 넣습니다. 식으로 넣는다면 `body('Run_daily')?['result']`입니다.
5. 처음 한 번 실행한 뒤 JSON의 운영일·원본 탭·사번이 맞는지 확인합니다.
6. 월이 바뀌면 스크립트 실행의 **원본 월 파일** 선택도 바꿉니다. 원본이 없는 달이나 날짜는 오류로 멈추며 이전 JSON을 덮어쓰지 않습니다.

## Power Automate B — Excel 연결형 접수

이 흐름은 웹에서 실제로 입력을 반영하려는 경우에만 필요합니다. 웹 계산형에는 필요하지 않습니다.

1. SharePoint → **파일이 만들어질 때(속성만)** 트리거를 만듭니다. 라이브러리와 폴더를 `긴조웹/요청`으로 지정합니다. 결과 폴더를 트리거로 선택하지 않습니다.
2. 트리거 설정 → **동시성 제어 켜기 / 병렬 처리 수준 1**로 설정합니다. 같은 상태출력 파일을 이 흐름 여러 개가 동시에 수정하지 않도록 합니다.
3. SharePoint → **파일 콘텐츠 가져오기**를 추가하고 트리거의 파일 Identifier를 선택합니다. 작업 이름을 `Get_request_content`로 바꿉니다.
4. Excel Online (Business) → **스크립트 실행**을 추가합니다. 상태출력 **시험 복사본**과 `웹 접수 처리` 스크립트를 선택하고 작업 이름을 `Run_submit`으로 바꿉니다.
5. `접수JSON`에는 가져온 파일의 UTF-8 JSON 내용을 전달합니다. 파일 콘텐츠가 `$content`를 가진 바이너리 형태로 나오는 일반적인 경우 식은 아래입니다.

```
base64ToString(body('Get_request_content')?['$content'])
```

실행 이력에서 파일 콘텐츠가 이미 JSON 문자열/객체로 보이고 `$content`가 없는 경우에는 아래 식을 사용합니다.

```
string(body('Get_request_content'))
```

6. SharePoint → **파일 만들기**를 추가해 `긴조웹/결과`에 저장합니다. 파일 이름은 아래 식, 파일 내용은 `Run_submit`의 **result**입니다.

```
concat('result-', json(body('Run_submit')?['result'])?['requestId'], '.json')
```

7. 조건을 추가합니다. `json(body('Run_submit')?['result'])?['type']`가 `ginjo-result`일 때만 회사 `상태출력-결과.json`을 같은 result로 업데이트합니다. `ginjo-error`를 최신 정상 결과 파일에 덮어쓰지 않습니다. 요청별 오류 파일은 6번에서 저장되어 HTML에 표시됩니다.
8. 읽기부터 시험합니다. HTML에서 폴더 연결 → **엑셀 결과 새로 읽기**를 누릅니다. `요청/req-요청번호.json`이 생성되고, 같은 요청번호의 `결과/result-요청번호.json`이 돌아오면 화면이 갱신됩니다.
9. 실제 원문을 붙여넣고 **엑셀에 접수**를 누릅니다. 실행이 완료된 다음 Excel A1·D5·수식설정 B2·제외 10명과 결과를 확인합니다. HTML은 다른 요청의 결과를 자기 결과로 표시하지 않습니다.

처리 스크립트는 원본 데일리의 날짜를 임의로 바꾸거나 외부 링크가 갱신됐다고 가정하지 않습니다. `데일리연결!B5`가 접수 운영일과 다르면 먼저 기존 Excel에서 날짜·원본 연결을 확인해야 합니다.

웹 접수는 A1, D5, 기준시각, 제외 명단, 수기 교육/예외, 해당 시간의 AA 기록을 변경합니다. 기존 추가기능·다른 흐름·수동 버튼과 동시에 같은 입력을 기록하지 않도록 시험 복사본에서 단독으로 사용하세요. 처리 실패 시 이전 입력을 복원하고 오류 JSON을 반환합니다. 복원 확인이 필요한 경우도 메시지로 표시합니다.

## 폴더 자동 접근이 안 될 때

- 웹 계산형: 데일리 JSON을 회사 SharePoint에서 다운로드해 HTML로 불러옵니다. 이후 원문·제외 입력의 계산은 바로 됩니다.
- 엑셀 연결형: 실제 상태출력 JSON을 먼저 불러온 뒤 ‘접수 JSON 다운로드’를 사용합니다. 그 파일을 회사 SharePoint의 `요청` 폴더에 올리고, 생성된 요청별 결과 JSON을 다운로드해 불러옵니다.
- SharePoint가 HTML을 미리보기·다운로드로 처리하는 것은 파일 오류가 아닙니다. 로컬로 내려받아 브라우저에서 열어 사용하세요.
- 원문 자동 수집은 포함하지 않았습니다. A1은 직접 붙여넣습니다.

## 보관·오류

- 회사 요청/결과 JSON에는 실제 직원 자료가 들어갑니다. 회사 권한이 설정된 폴더에서만 보관하고, 보존 기간·삭제 정책은 회사 기준을 따르세요. 공개 Gist에 올리지 않습니다.
- HTML 자체는 원문을 외부 서버로 보내지 않고, 자동으로 로컬 저장소에 보관하지 않습니다. 사용자가 누른 접수·내보내기만 파일을 만듭니다.
- 샘플 JSON에는 sample=true가 들어 있어 불러와도 실제 연결로 표시하지 않습니다.
- 창을 닫으면 브라우저의 입력·이력은 사라집니다. 회사 Excel/요청 파일에 접수된 내용은 별개입니다.
- 문제 시 ‘오류 상세’를 복사하고, Power Automate 실행 이력의 실패 작업도 확인하세요. GPT에 실제 원문을 붙일 필요는 없습니다.
