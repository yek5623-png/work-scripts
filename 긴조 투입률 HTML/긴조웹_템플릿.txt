HTML의 ‘연결 · 사용 방법 → JSON 붙여넣기’에 넣습니다.\n5. 실제 A1 원문을 붙여넣고 ‘웹에서 계산’을 누릅니다. 샘플에서 실제 파일로 바꾸면 샘플 원문은 지웁니다.\n\n### 엑셀 연결형\n\n1. 상태출력 복사본에 `스크립트/긴조 투입률 업데이트.txt`를 한 번 실행해 20261116.6을 설치합니다.\n2. 같은 파일에서 `스크립트/상태출력 웹 내보내기.txt`를 저장·실행합니다.\n3. 출력 JSON을 HTML의 ‘JSON 붙여넣기’로 불러옵니다. 기존 Excel 결과가 나타나는지 확인합니다.\n4. 아래 자동 연결을 구성한 뒤 원문을 웹에서 접수합니다. 입력이 실제로 반영되기 전에는 ‘엑셀 처리 대기’로 표시합니다.\n\n## 회사 폴더 만들기\n\n쓰기 권한이 있는 회사 SharePoint 문서 라이브러리에 `긴조웹` 폴더를 만들고 아래처럼 구성합니다. 폴더 위치는 회사에서 허용하는 곳으로 정하세요.\n\n```\n긴조웹/\n  데일리.json\n  상태출력-결과.json\n  요청/\n  결과/\n```\n\n처음 두 JSON은 각 내보내기 스크립트의 실제 출력으로 만듭니다. 빈 `{}`나 샘플 파일을 실제 자료로 사용하지 않습니다. 웹 계산형만 쓸 때는 `데일리.json`만 있으면 됩니다.\n\n회사 PC에서 이 폴더를 OneDrive로 동기화하고 ‘항상 이 장치에 유지’를 선택합니다. HTML의 ‘동기화 폴더 연결’에서 바로 이 `긴조웹` 폴더를 고릅니다. Excel 연결형은 접수 저장을 위해 읽기/쓰기 허용이 필요합니다. 웹 계산형은 읽기만 요청합니다.\n\n폴더 접근이 브라우저나 회사 정책에 막히면 ‘JSON 직접 불러오기’ 또는 ‘JSON 붙여넣기’를 사용합니다. 폴더 선택이 되는 경우에만 5초마다 파일 변경을 확인합니다. 이 5초는 회사 흐름·OneDrive의 실제 처리 속도를 보장하는 시간이 아닙니다.\n\n## Power Automate A — 데일리 자동 내보내기\n\n1. 회사 Power Automate에서 예약된 클라우드 흐름을 만듭니다. 주기는 **5분**, 시간대는 Seoul로 설정합니다. Office Scripts 실행 제한을 고려해 1초·수초 간격으로 만들지 않습니다.\n2. Excel Online (Business) → **스크립트 실행**을 추가하고 원본 데일리 월 파일과 `데일리 웹 내보내기`를 선택합니다. 작업 이름을 `Run_daily`로 바꿉니다.\n3. `기준시각`은 비워 두면 실행 시각을 사용합니다. 05시 이전에는 전날 운영일 탭을 읽습니다.\n4. SharePoint → **파일 업데이트**로 회사 `긴조웹/데일리.json`을 선택합니다. 파일 내용에는 `Run_daily`의 동적 콘텐츠 **result**를 넣습니다. 식으로 넣는다면 `body('Run_daily')?['result']`입니다.\n5. 처음 한 번 실행한 뒤 JSON의 운영일·원본 탭·사번이 맞는지 확인합니다.\n6. 월이 바뀌면 스크립트 실행의 **원본 월 파일** 선택도 바꿉니다. 원본이 없는 달이나 날짜는 오류로 멈추며 이전 JSON을 덮어쓰지 않습니다.\n\n## Power Automate B — Excel 연결형 접수\n\n이 흐름은 웹에서 실제로 입력을 반영하려는 경우에만 필요합니다. 웹 계산형에는 필요하지 않습니다.\n\n1. SharePoint → **파일이 만들어질 때(속성만)** 트리거를 만듭니다. 라이브러리와 폴더를 `긴조웹/요청`으로 지정합니다. 결과 폴더를 트리거로 선택하지 않습니다.\n2. 트리거 설정 → **동시성 제어 켜기 / 병렬 처리 수준 1**로 설정합니다. 같은 상태출력 파일을 이 흐름 여러 개가 동시에 수정하지 않도록 합니다.\n3. SharePoint → **파일 콘텐츠 가져오기**를 추가하고 트리거의 파일 Identifier를 선택합니다. 작업 이름을 `Get_request_content`로 바꿉니다.\n4. Excel Online (Business) → **스크립트 실행**을 추가합니다. 상태출력 **시험 복사본**과 `웹 접수 처리` 스크립트를 선택하고 작업 이름을 `Run_submit`으로 바꿉니다.\n5. `접수JSON`에는 가져온 파일의 UTF-8 JSON 내용을 전달합니다. 파일 콘텐츠가 `$content`를 가진 바이너리 형태로 나오는 일반적인 경우 식은 아래입니다.\n\n```\nbase64ToString(body('Get_request_content')?['$content'])\n```\n\n실행 이력에서 파일 콘텐츠가 이미 JSON 문자열/객체로 보이고 `$content`가 없는 경우에는 아래 식을 사용합니다.\n\n```\nstring(body('Get_request_content'))\n```\n\n6. SharePoint → **파일 만들기**를 추가해 `긴조웹/결과`에 저장합니다. 파일 이름은 아래 식, 파일 내용은 `Run_submit`의 **result**입니다.\n\n```\nconcat('result-', json(body('Run_submit')?['result'])?['requestId'], '.json')\n```\n\n7. 조건을 추가합니다. `json(body('Run_submit')?['result'])?['type']`가 `ginjo-result`일 때만 회사 `상태출력-결과.json`을 같은 result로 업데이트합니다. `ginjo-error`를 최신 정상 결과 파일에 덮어쓰지 않습니다. 요청별 오류 파일은 6번에서 저장되어 HTML에 표시됩니다.\n8. 읽기부터 시험합니다. HTML에서 폴더 연결 → **엑셀 결과 새로 읽기**를 누릅니다. `요청/req-요청번호.json`이 생성되고, 같은 요청번호의 `결과/result-요청번호.json`이 돌아오면 화면이 갱신됩니다.\n9. 실제 원문을 붙여넣고 **엑셀에 접수**를 누릅니다. 실행이 완료된 다음 Excel A1·D5·수식설정 B2·제외 10명과 결과를 확인합니다. HTML은 다른 요청의 결과를 자기 결과로 표시하지 않습니다.\n\n처리 스크립트는 원본 데일리의 날짜를 임의로 바꾸거나 외부 링크가 갱신됐다고 가정하지 않습니다. `데일리연결!B5`가 접수 운영일과 다르면 먼저 기존 Excel에서 날짜·원본 연결을 확인해야 합니다.\n\n웹 접수는 A1, D5, 기준시각, 제외 명단, 수기 교육/예외, 해당 시간의 AA 기록을 변경합니다. 기존 추가기능·다른 흐름·수동 버튼과 동시에 같은 입력을 기록하지 않도록 시험 복사본에서 단독으로 사용하세요. 처리 실패 시 이전 입력을 복원하고 오류 JSON을 반환합니다. 복원 확인이 필요한 경우도 메시지로 표시합니다.\n\n## 폴더 자동 접근이 안 될 때\n\n- 웹 계산형: 데일리 JSON을 회사 SharePoint에서 다운로드해 HTML로 불러옵니다. 이후 원문·제외 입력의 계산은 바로 됩니다.\n- 엑셀 연결형: 실제 상태출력 JSON을 먼저 불러온 뒤 ‘접수 JSON 다운로드’를 사용합니다. 그 파일을 회사 SharePoint의 `요청` 폴더에 올리고, 생성된 요청별 결과 JSON을 다운로드해 불러옵니다.\n- SharePoint가 HTML을 미리보기·다운로드로 처리하는 것은 파일 오류가 아닙니다. 로컬로 내려받아 브라우저에서 열어 사용하세요.\n- 원문 자동 수집은 포함하지 않았습니다. A1은 직접 붙여넣습니다.\n\n## 보관·오류\n\n- 회사 요청/결과 JSON에는 실제 직원 자료가 들어갑니다. 회사 권한이 설정된 폴더에서만 보관하고, 보존 기간·삭제 정책은 회사 기준을 따르세요. 공개 Gist에 올리지 않습니다.\n- HTML 자체는 원문을 외부 서버로 보내지 않고, 자동으로 로컬 저장소에 보관하지 않습니다. 사용자가 누른 접수·내보내기만 파일을 만듭니다.\n- 샘플 JSON에는 sample=true가 들어 있어 불러와도 실제 연결로 표시하지 않습니다.\n- 창을 닫으면 브라우저의 입력·이력은 사라집니다. 회사 Excel/요청 파일에 접수된 내용은 별개입니다.\n- 문제 시 ‘오류 상세’를 복사하고, Power Automate 실행 이력의 실패 작업도 확인하세요. GPT에 실제 원문을 붙일 필요는 없습니다.\n\n## 검증 범위\n\n이 묶음은 브라우저 화면, 계산, JSON 변환, 요청번호 일치, Office Script 모의 실행을 검사합니다. 실제 회사 계정의 권한·동기화·Power Automate 흐름은 회사 환경에서 처음 한 번 확인해야 합니다.\n\n참고 문서:\n- function parseShiftDefinition(shiftText        )                               {
const clean = normalizeText(shiftText).replace(/（/g, "(").replace(/）/g, ")")
const range = clean.match(/(?:^|[^0-9])(\d{2})(\d{2})\s*[-–—~～]\s*(\d{2})(\d{2})(?!\d)/)
if (range) {
    const startHour = Number(range[1])
    const startMinute = Number(range[2])
    const endHour = Number(range[3])
    const endMinute = Number(range[4])
    if (!isValidHourMinute(startHour, startMinute)) return null
    // 종료 시각 24~29시는 다음 날 00~05시입니다(예: 2000-2900).
    if (endHour < 0 || endHour > 29 || endMinute < 0 || endMinute > 59) return null
    let startMinutes = startHour * 60 + startMinute
    let endMinutes = endHour * 60 + endMinute
    if (endMinutes < startMinutes) endMinutes += 1440
    if (endMinutes === startMinutes || endMinutes - startMinutes > 1440) return null
    const codeMatch = clean.match(/\(\s*(209|105)\s*\)/)
    const code = codeMatch ? codeMatch[1] : ""
    if (code === "105") {
        // 4.5시간 구간의 끝 30분 또는 시작 30분을 휴무로 제외합니다.
        if (endMinutes - startMinutes === 270) {
            if (startMinute === 30 && endMinute === 0) startMinutes += 30
            else if (startMinute === 0 && endMinute === 30) endMinutes -= 30
        }
        const workMinutes = endMinutes - startMinutes
        if (startMinutes >= 1440) { startMinutes -= 1440; endMinutes -= 1440 }
        // 105 단축도 4시간을 넘을 수 있으므로 표시된 종료 시각까지 근무합니다.
        return { startMinutes, endMinutes, shiftHours: workMinutes / 60, mealMinutes: 0 }
    }
    const elapsedMinutes = endMinutes - startMinutes
    // (209) 코드보다 명시된 출퇴근 시각을 우선합니다.
    // ne1100-1700(209) 같은 단축 근무도 해당 구간 그대로 인정합니다.
    // 식사시간은 기존처럼 9시간 이상 구간에서만 1시간 제외합니다.
    const mealMinutes = elapsedMinutes >= 540 ? 60 : 0
    const shiftHours = (elapsedMinutes - mealMinutes) / 60
    return { startMinutes, endMinutes, shiftHours, mealMinutes }
}

// 기존 5시8H 형식도 계속 지원합니다.
let match = clean.match(/(\d{1,2})\s*시\s*(\d+(?:\.\d+)?)\s*h/i)
if (!match) match = clean.match(/(?:^|\D)(\d{1,2})\s*[:：]\s*00.*?(\d+(?:\.\d+)?)\s*h/i)
if (!match) return null
const startHour = Number(match[1])
const shiftHours = Number(match[2])
if (!isValidHourMinute(startHour, 0) || !Number.isFinite(shiftHours) || shiftHours <= 0) return null
const startMinutes = startHour * 60
const mealMinutes = shiftHours >= 8 ? 60 : 0
return { startMinutes, endMinutes: startMinutes + Math.round(shiftHours * 60) + mealMinutes, shiftHours, mealMinutes }
}

function parseScheduledWorkHours(value        )                {
const text = normalizeText(value)
if (!/^(?:\d+(?:\.\d+)?|\.\d+)$/.test(text)) return null
const hours = Number(text)
return Number.isFinite(hours) && hours > 0 ? hours : null
}

function parseHourStartMinutes(timeText        , timeValue                           )                {
const clean = normalizeText(timeText)

// 숫자 시각, 운영시간 24~28시와 '28시(04)' 표기를 지원합니다.
const operationHour = clean.match(/^(\d{1,2})(?:\s*시)?(?:\s*[（(]\s*\d{1,2}\s*[）)])?$/)
if (operationHour) {
    const hour = Number(operationHour[1])
    if (hour >= 0 && hour <= 28) return (hour % 24) * 60
}
const lateHour = clean.match(/^(2[4-8])\s*(?:[:：]\s*(\d{1,2})|시(?:\s*(\d{1,2})\s*분)?)$/)
if (lateHour) {
    const minute = Number(lateHour[2] || lateHour[3] || 0)
    if (minute >= 0 && minute < 60) return (Number(lateHour[1]) % 24) * 60 + minute
}

let match = clean.match(/^(\d{1,2})\s*[:：]\s*(\d{1,2})(?:\s*[:：]\s*\d{1,2})?$/)

if (match) {
    const hour = Number(match[1])
    const minute = Number(match[2])
    if (isValidHourMinute(hour, minute)) return hour * 60 + minute
}

match = clean.match(/^(\d{1,2})\s*시(?:\s*(\d{1,2})\s*분)?$/)

if (match) {
    const hour = Number(match[1])
    const minute = match[2] ? Number(match[2]) : 0
    if (isValidHourMinute(hour, minute)) return hour * 60 + minute
}

if (typeof timeValue === "number" && !isNaN(timeValue)) {
    const dayFraction = timeValue - Math.floor(timeValue)
    const totalMinutes = Math.round(dayFraction * 1440)
    const normalizedMinutes = ((totalMinutes % 1440) + 1440) % 1440
    return normalizedMinutes
}

return null
}

function formatDurationText(value        )         {

let found = false

    found = true
    const amount = Number(match[1])
    const unit = match[2]
    totalSeconds += amount * (unit === "일" ? 86400 : unit === "시간" || unit === "시" ? 3600 : unit === "분" ? 60 : 1)

const minutes = Math.floor(totalSeconds / 60) % 60

}
