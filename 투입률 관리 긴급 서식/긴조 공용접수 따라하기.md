# 긴조 공용 접수 — 처음 한 번 설정하기

팀장님들은 추가 기능을 설치하지 않습니다. 회사의 접수 목록을 열고 **새 항목 → 원문 붙여넣기 → 저장**만 합니다. 이후 클라우드가 긴조 엑셀에 기록합니다. 설정한 사람의 PC와 엑셀이 꺼져 있어도 클라우드 흐름은 실행됩니다.

**시험판입니다. 코드 모의검사는 통과했지만 실제 회사 계정에서의 실행은 아직 확인하지 못했습니다. 현재 잘되는 파일을 복사해서 시험하세요.**

- D5는 **목록에서 저장한 시각**입니다. 처리 완료 시각이나 붙여넣기 직전 시각이 아닙니다.
- AA는 저장한 시각의 구간에 누적합니다. 같은 시간대에는 마지막 접수 결과를 남깁니다. 28~29 다음은 오전 5시 첫 접수에서 05~06으로 시작합니다.
- 엑셀 반영은 클라우드 처리 후에 이루어집니다. 바로 끝난다는 보장은 없습니다. 원문은 접수 목록에 먼저 남습니다.
- 원본 데일리의 수정 내용은 **다음 접수 때** 직접 읽어 반영합니다.
- 현행 긴조와 같은 9구간, 직원표 6~140행을 가져옵니다. 직원표가 140행을 넘는 서식은 범위 조정이 먼저 필요합니다.
- 원문은 Excel 한 칸 제한 때문에 **32,767자 이하**여야 합니다.

먼저 아래 순서대로 1~6번을 진행합니다. 코드 안의 글자는 수정하지 않아도 됩니다.

## 1. 시험용 엑셀을 한 개 만들기

1. 지금 잘되는 **긴조 엑셀**을 Excel 웹에서 엽니다.
2. 왼쪽 위 **파일 → 다른 이름으로 저장 → 복사본 저장**을 누릅니다. 메뉴 이름이 다르면 파일 이름 옆 메뉴에서 **복사본 만들기/복사본 저장**을 찾습니다.
3. 이름을 **긴조_클라우드시험.xlsx**로 정합니다. 회사 OneDrive 또는 팀 SharePoint에 저장합니다. PC에만 내려받은 파일은 사용할 수 없습니다.
4. **새로 만든 복사본**을 엽니다. 위쪽 파일 이름이 `긴조_클라우드시험`인지 확인합니다.
5. 이 복사본에서 **긴조 자동 기록** 추가 기능을 열고 **끄기**를 누릅니다.

원래 쓰던 파일은 계속 사용하셔도 됩니다. 시험 파일에서는 기존 새로고침 버튼을 누르거나 A1을 직접 수정하지 않습니다. 두 자동화가 동시에 쓰는 것을 막기 위한 순서입니다.

## 2. 원문을 받을 접수 목록 만들기

1. [Microsoft 365](https://www.microsoft365.com/)에 **회사 계정**으로 로그인합니다.
2. 왼쪽 위 점 아홉 개 **앱 시작 관리자 → 모든 앱 → Lists(목록)**를 누릅니다. 안 보이면 앱 검색에서 `Lists`를 검색합니다.
3. **새 목록 → 빈 목록**을 누릅니다.
4. 이름에 **긴조 원문 접수**를 씁니다.
5. 저장 위치에는 **현재 데일리 원본을 보관하는 팀 SharePoint 사이트**를 고릅니다. `내 목록` 대신 팀 사이트에 만들면 다음 단계에서 찾기 쉽습니다.
6. **만들기**를 누릅니다.
7. 목록의 오른쪽 **열 추가 → 여러 줄 텍스트**를 누릅니다. 이름은 **원문**, 필수 입력은 **예**로 정합니다. 텍스트 종류는 **일반 텍스트**를 사용합니다. `기존 텍스트에 변경 내용 추가`는 **아니요**입니다.
8. 다시 **열 추가 → 여러 줄 텍스트**를 눌러 **처리결과** 열을 만듭니다. 필수 입력은 **아니요**로 둡니다.
9. 맨 처음부터 있던 **제목** 열의 메뉴를 열어 **열 설정 → 편집**으로 들어갑니다. 기본값에 **긴조 접수**를 넣고 저장합니다. 기본값 설정이 안 보이면 접수할 때 제목에 `긴조 접수`를 입력해도 됩니다.

목록 주소를 메모장에 복사해 둡니다. 팀장들이 나중에 사용할 주소입니다. 아직 시험 접수는 하지 마세요.

## 3. 스크립트 두 개 저장하기

스크립트는 **한 번만 저장**합니다. 매번 실행 버튼을 누르지 않습니다.

1. `긴조_클라우드시험.xlsx`로 돌아옵니다.
2. 위쪽 **자동화 → 새 스크립트 → 코드 편집기**를 누릅니다.
3. 코드 칸 안을 한 번 클릭한 뒤 **Ctrl+A**로 기본 코드를 모두 선택합니다.
4. **긴조 공용접수 1 원본읽기** 파일의 내용을 전부 복사해 붙여넣습니다. 파일 이름이나 이 설명은 붙이지 말고 코드 내용만 넣습니다.
5. 편집기 위쪽 스크립트 이름도 **긴조 공용접수 1 원본읽기**로 바꿉니다. 저장 표시가 끝날 때까지 기다립니다.
6. 다시 **새 스크립트**를 만들어 **긴조 공용접수 2 자동기록** 파일의 내용을 전부 붙입니다. 이름도 **긴조 공용접수 2 자동기록**으로 저장합니다.

**지금은 실행을 누르지 마세요.** 다음 단계의 Power Automate가 접수 자료를 넣고 실행합니다. 스크립트가 두 개 보이면 이 단계는 끝입니다.

## 4. 접수하면 작동하는 흐름 만들기

[Power Automate](https://make.powerautomate.com/)를 **같은 회사 계정**으로 엽니다. 화면 위쪽 환경은 회사에서 기본으로 쓰는 환경을 사용합니다.

### 4-1. 시작 조건 고르기

1. 왼쪽 **만들기 → 자동화된 클라우드 흐름**을 누릅니다.
2. 이름에 **긴조 접수 자동 기록**을 씁니다.
3. 시작 조건 검색 칸에 **SharePoint**를 검색합니다.
4. **항목이 만들어질 때/항목이 만들어진 경우(When an item is created)**를 고릅니다. `수정될 때`가 들어간 항목은 고르지 않습니다.
5. **만들기**를 누릅니다. 로그인 요청이 나오면 회사 계정으로 연결합니다.
6. 첫 번째 상자의 **사이트 주소**는 2번에서 목록을 만든 팀 사이트, **목록 이름**은 **긴조 원문 접수**로 고릅니다.
7. 첫 번째 상자의 **설정** 탭을 엽니다. 예전 화면은 상자 오른쪽 **… → 설정**입니다.
8. **동시성 제어**를 **켬**으로 바꾸고 **병렬 처리 수준/동시 실행 수**를 **1**로 정합니다. 한 접수씩 처리하게 하는 설정입니다.

### 4-2. 원본 데일리를 읽는 상자 추가하기

1. 첫 번째 상자 아래 **+ → 작업 추가**를 누릅니다.
2. **Excel Online (Business)**를 검색하고 **스크립트 실행(Run script)**을 고릅니다.
3. 상자 메뉴 **… → 이름 바꾸기**로 이름을 **원본읽기**로 정합니다. 새 화면에서는 상자 제목을 눌러 바꿀 수 있습니다.
4. 아래 표대로 고릅니다. **파일 칸은 폴더 아이콘으로 실제 파일을 선택**하세요. 공유 링크를 붙이지 않습니다.

| 화면의 칸 | 고를 내용 |
|---|---|
| 위치 | 원본 데일리가 저장된 팀 SharePoint 사이트 |
| 문서 라이브러리 | 원본 데일리가 들어 있는 문서함. 보통 `문서/Documents` |
| 파일 | 이번 달 **원본** `긴급조치 DailySheet.(26.11)(NEW).xlsx` |
| 스크립트 | **긴조 공용접수 1 원본읽기** |
| 접수시각 | 첫 번째 SharePoint 상자의 **만든 날짜/Created** |
| 원본연월 | 키보드로 **2026-11** 입력 |

`만든 날짜`는 직접 날짜를 쓰는 칸이 아닙니다. **접수시각 칸 클릭 → 동적 콘텐츠(번개 모양) → SharePoint 항목 중 만든 날짜/Created 선택**입니다. 현재 시각이나 수정한 날짜는 고르지 않습니다.

스크립트 이름 아래에 추가 칸이 안 보이면 **고급 매개 변수/모두 표시**를 펼칩니다. 그래도 없으면 스크립트 저장을 확인한 뒤 이 상자를 삭제하고 다시 추가합니다.

### 4-3. 시험용 긴조 엑셀에 기록하는 상자 추가하기

1. **원본읽기** 아래 **+ → 작업 추가**를 누릅니다.
2. 다시 **Excel Online (Business) → 스크립트 실행**을 추가합니다.
3. 상자 이름을 **자동기록**으로 바꿉니다.
4. 아래 표대로 고릅니다.

| 화면의 칸 | 고를 내용 |
|---|---|
| 위치 | 시험용 파일을 저장한 회사 OneDrive 또는 팀 SharePoint 사이트 |
| 문서 라이브러리 | 시험용 파일이 들어 있는 문서함 |
| 파일 | **긴조_클라우드시험.xlsx** |
| 스크립트 | **긴조 공용접수 2 자동기록** |
| 원문 | 첫 번째 SharePoint 상자의 **원문** |
| 접수시각 | 첫 번째 SharePoint 상자의 **만든 날짜/Created** |
| 접수번호 | 첫 번째 SharePoint 상자의 **ID** |
| 데일리자료 | 바로 앞 **원본읽기** 상자의 **결과/result** |

원문·접수시각·접수번호·데일리자료도 모두 **동적 콘텐츠에서 선택**합니다. `ID`라는 글자나 `결과`라는 글자를 키보드로 입력하지 않습니다. `데일리자료`에는 **본문/Body 전체**가 아닌 **결과/result** 하나를 넣습니다.

두 스크립트의 **접수시각**에는 똑같은 SharePoint **만든 날짜**가 들어가야 합니다.

### 4-4. 접수 목록에 처리결과 표시하기

1. **자동기록** 아래 **+ → 작업 추가**를 누릅니다.
2. **SharePoint → 항목 업데이트(Update item)**를 고릅니다.
3. 사이트 주소와 목록 이름을 첫 번째 상자와 같게 고릅니다.
4. **ID**에는 첫 번째 SharePoint 상자의 **ID**를 고릅니다.
5. **제목**에는 첫 번째 SharePoint 상자의 **제목/Title**을 고릅니다.
6. **원문** 칸이 보이면 첫 번째 SharePoint 상자의 **원문**을 고릅니다. 기존 원문을 유지하기 위한 연결입니다.
7. **처리결과**에는 바로 앞 **자동기록** 상자의 **결과/result**를 고릅니다.
8. 오른쪽 위 **저장**을 누릅니다. 오류가 나오지 않는지 확인합니다.

최종 상자는 위에서 아래로 **항목이 만들어질 때 → 원본읽기 → 자동기록 → 항목 업데이트** 네 개입니다.

## 5. 시험 접수 한 건 보내기

1. 접수 목록 **긴조 원문 접수**를 엽니다.
2. **새 항목/새 항목 추가**를 누릅니다.
3. 제목은 `긴조 접수`로 둡니다. **원문** 칸에 평소 A1에 넣던 원문을 붙입니다. **처리결과**는 비워 둡니다.
4. **저장**을 누릅니다. 이 시각이 D5에 기록됩니다.
5. Power Automate에서 왼쪽 **내 흐름 → 긴조 접수 자동 기록 → 실행 기록**을 엽니다. 방금 실행이 **성공**인지 확인합니다. 아직 실행 중이면 완료를 기다립니다.
6. `긴조_클라우드시험.xlsx`를 열어 **상태출력 A1에 원문, D5에 저장 시각, AA에 해당 구간**이 생겼는지 확인합니다.
7. 접수 목록을 새로고침해 **처리결과**에 `완료`가 포함되어 있는지 봅니다. `건너뜀`은 같은 접수를 이미 처리했거나 더 최신 접수가 있다는 뜻입니다.
8. 한 번 더 새 항목으로 접수합니다. 같은 시간대는 같은 AA 줄이 바뀌고 이전 시간대 줄은 남아야 합니다.
9. 엑셀을 닫고 다시 목록에서 새 접수를 해봅니다. 실행 기록이 성공하는지 확인합니다.

처리결과는 접수 내역 안내입니다. 팀에 공유하는 결과는 평소처럼 엑셀 AA열에서 봅니다. 실행이 실패하면 원문은 목록에 남습니다. 실패를 정상 결과로 표시하지 않습니다.

## 6. 다른 팀장들에게 사용하게 하기

시험 성공을 확인한 뒤 진행합니다.

1. 접수 목록 오른쪽 위 **공유**를 누르고 팀장 이름을 넣습니다. 권한은 **항목 편집 가능/편집 가능**을 고릅니다. `보기 가능`만 주면 새 접수를 못 합니다. 회사 정책에 따라 링크만으로 권한이 생기지 않을 수 있습니다.
2. 결과를 보는 `긴조_클라우드시험.xlsx`에도 팀장들에게 보기 권한을 줍니다. 명단·예외를 직접 수정할 담당자만 편집 권한을 유지합니다.
3. 목록 주소와 엑셀 주소를 함께 알려줍니다. XML이나 스크립트를 보내지 않습니다.

팀장들에게는 아래 네 줄만 알려주면 됩니다.

> 원문 접수 목록을 열어 주세요.
> ‘새 항목’을 눌러 원문을 붙이고 ‘저장’하세요.
> 접수 건을 수정하지 말고, 다시 입력할 때도 ‘새 항목’을 만드세요.
> 결과는 긴조 엑셀에서 보세요. A1에 직접 붙이지 않아도 됩니다.

처음 다른 팀장 한 명이 접수할 때는 본인 PC를 꺼둔 상태로 결과까지 확인하세요. 이 확인이 끝나면 시험 파일을 실제 운영 파일로 사용할 수 있습니다. 기존 파일의 자동 기록은 기존 파일에서만 계속 작동하므로, 어느 파일을 운영할지 팀에 명확히 알려 주세요.

## 다음 달에 할 일 — 한 상자만 수정

Power Automate에서 **긴조 접수 자동 기록 → 편집 → 원본읽기**를 엽니다.

| 바꿀 칸 | 12월 예시 |
|---|---|
| 파일 | `긴급조치 DailySheet.(26.12)(NEW).xlsx` 선택 |
| 원본연월 | `2026-12` 입력 |

저장합니다. 다른 상자와 스크립트는 그대로 둡니다. **운영일은 오전 5시에 바뀝니다.** 12월 1일 00~04시는 아직 11월 30일 자료를 사용하므로, 12월 연결 변경은 **12월 1일 오전 5시 이후 첫 접수 전**에 합니다. 1월은 `2027-01`처럼 연도도 바꿉니다.

|---|---|
| Lists 또는 Power Automate를 사용할 수 없음 | 회사에서 사용을 허용하는지 담당자에게 확인합니다. 별도 유료 결제를 먼저 하지 마세요. |
| 원본 파일이 선택 목록에 안 보임 | 폴더 아이콘으로 찾아봅니다. 같은 계정에 그 파일을 읽을 권한이 있어야 합니다. |
| 스크립트 실행에 매개 변수 칸이 없음 | 스크립트 저장을 확인하고 해당 ‘스크립트 실행’ 상자를 다시 추가합니다. |
| 추가 기능을 먼저 끄라는 오류 | 시험 파일에서 긴조 자동 기록 패널을 열어 ‘끄기’를 누릅니다. |
| 원본 월/날짜 탭 오류 | 원본읽기의 파일과 원본연월을 확인합니다. 탭 예시는 `긴급 11(14)`입니다. |
| 흐름은 실행됐지만 실패 | 실행 기록에서 빨간 상자를 눌러 오류를 확인합니다. 수정 후 실패한 실행의 **다시 제출/Resubmit**을 사용하면 같은 접수시각으로 재시도합니다. 원문을 다른 시각에 새로 접수하는 것과 다릅니다. |
| 목록의 접수 건을 수정했는데 재실행 안 됨 | 새 접수만 실행하도록 만들었습니다. 같은 원문을 다시 접수하려면 ‘새 항목’을 만듭니다. |
| 엑셀에 반영되기 전 | 실행 기록이 완료됐는지 확인합니다. 목록의 저장과 엑셀 반영 사이에는 지연이 있을 수 있습니다. |

흐름은 설정한 회사 계정의 연결로 실행됩니다. 그 계정의 파일 권한이 없어지거나 연결 재로그인이 필요해지면 소유자가 연결을 복구해야 합니다. 원문은 회사 SharePoint와 회사 엑셀 안에서 처리하며, 기존 공개 코드 사이트로 보내지 않습니다.

동시에 같은 엑셀을 직접 편집하면 커넥터와 충돌할 수 있으므로, 접수는 목록으로 모으고 근무 예외 등 수기 수정은 처리가 끝난 때 합니다. 출근 원본을 읽는 스크립트에는 쓰기 명령이 없습니다. 시험 파일의 데일리 지정 구간은 값으로 바뀌며, 수식설정 B2는 마지막 접수시각으로 고정됩니다. 기존 외부 링크 새로고침 버튼을 시험 파일에 섞어 사용하지 않습니다.
